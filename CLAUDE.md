# Il Mazzo — guide for Claude Code

Italian flashcards for one learner (Nassim), in a single HTML file served by GitHub Pages at https://nassim55.github.io/il-mazzo/. Read `README.md` for what the app does.

## Workflow for every change

1. Make the change in `index.html` (markup, CSS, data and code all live there).
2. Add or update tests in `tests/` for any new behaviour.
3. Run `npm test` — **every suite must pass** before committing. Run one suite with `node tests/<name>.test.js` to see each check.
4. Commit with a descriptive message and push:
   - **On a laptop** (Claude Code desktop or terminal): push to `main`. GitHub Actions re-tests it and publishes the site.
   - **In Claude Code on the web**: push your `claude/…` branch as usual. GitHub Actions tests it and, if every suite passes, merges it into `main` and publishes. If a test fails, the branch is not merged — fix it and push again.
   The live site updates a minute or two after `main` passes.

If a suite fails, fix the cause; never weaken a test to make it pass unless the behaviour change was requested (then update the test and say why in the commit).

## Rules that protect the user's data

- **Never rename saved-data keys.** Progress lives in each browser's localStorage under keys such as `sostantivi-stats-v1`, `verbi-regolari-stats` (old `{attempts, wrongs}` format — keep it), `aggettivi-stats-v1`, `frasi-stats-v1`, their `-iten` / `-listen` variants, the `:srs` review schedules, the `*-assoc-v1` association keys, the story's `racconto-stats-*` keys and reading progress `mazzo-story-v1`, `flipcards-subject`, `mazzo-audio-v1` and `mazzo-ripasso-dir`. Renaming any of them silently wipes the user's history.
- New saved data goes in new keys, and must be added to `storageKeys()` so backups include it. New *progress* data must also be added to `syncedKeys()` with a merge rule (and a test in `sync-merge`).
- `mazzo-sync-meta-v1` and `mazzo-sync-base-v1` are per-device sync bookkeeping: never in backups, never synced.
- `tests/fixtures/original-*.html` are the user's original standalone games, used to prove the ports haven't drifted. Never edit them.

## Behaviour conventions

- No regressions: existing features keep working exactly as before unless the user asks otherwise.
- British English in UI text and notes ("practise" as the verb, "colour").
- Answers stay lenient where it doesn't matter (accents, punctuation, capitals) and strict where it does (articles for nouns, *tu*/*Lei* in phrases, pronouns for verbs).
- History notes: accurate etymology, English cognates, links to other words in the deck, false friends flagged; say "uncertain"/"perhaps" when the origin is disputed.
- Verb pronunciations: the syllabifier marks stress by rule; verbs with early or unusual stress need a `pronMap` entry (see `abitare`, `significare`, `creare`).
- Frequency rankings blend written (wordfreq) and spoken (OpenSubtitles) counts, weighted by part-of-speech share in the Italian UD treebanks; method notes sit beside each data block. The adjectives' first 100 are the user's original game (keep them first and unchanged — `adjectives-vs-original` checks); newer ones follow in `adjData` and in the themes, with history notes in `ADJ_NEW_NOTES`. Adding adjectives can change how story and sentence words resolve: compare every resolution before and after, and pin senses where needed (chapter 1's *solo* = only).
- Layout must work from desktop down to 320px phones with no sideways scroll.

## Sentences (*Scrittura*)

- `SENTENCE_DATA`: `[level, person, Italian, English, other correct Italian, other correct English]`. Present tense only (until the user says otherwise); every word must be in the deck or a small word in `STORY_FN` — the start-up check warns otherwise, and the tests fail. Plurals resolve to their singular card (`sentencePluralNoun`); give a word a sense in `SENTENCE_CH.senses` when it could be read two ways.
- The subject pronoun is accepted with or without automatically (`sentenceAccepted`); list other genuinely correct Italian as alternatives. Write the English word for word in the Italian's order, even where it isn't proper English (the user's choice): simple present, no do/does/don't, verb before subject where the Italian has it, only the Italian's articles and prepositions, adjectives after the noun, idioms as they are; keep natural English in the accepted alternatives. Where the word-for-word reads oddly, add the natural English to `SENTENCE_NATURAL` (shown under the prompt, English → Italian only). Mark every "you" as (tu) or (voi).
- Keys are slugs of the Italian (`sentenceKey`), so editing a sentence's Italian starts its history afresh.
- Sentence kinds: each level has a type (`presente` | `piacere`); `activeSentenceTypes()` (stored in the verb-persons store under `sentences`) narrows the section in `applySubject` and Ripasso in `dueList`. In *Mi piace* sentences the person code is the grammatical subject: `cosa` / `cose` for a thing (no subject pronoun added), or a real person (*Mi manchi*: `tu`).
- Section charts live in `SECTION_CHARTS` (one function per panel key), shared by the setup's side panel and the in-round *▦ chart* button (`openChart`), so they can't drift apart. A new chart goes there, with its title in `CHART_TITLES`. While a chart is open it owns the keyboard (Escape closes it, Enter never submits).
- The in-round chart can be pinned (`chartPinned`, stored per device as `mazzo-chart-pinned-v1`): `.chart-overlay.pinned` lets clicks and keys through (the keydown handler only holds the keys for an open, *unpinned* chart) and `body.chart-docked` makes room — a 440px right gutter from 1000px wide, below the round on narrower screens. `syncPinnedChart()` runs on every view change and from `updateChartBtn()`, so a pinned chart follows the section and shows only in the game view. `closeChart()` from ×, Escape or a click outside unpins; leaving the round calls `closeChart({ keepPin: true })`. Tests: `tests/chart-pin.test.js`.
- Preposizioni (`PREP_DATA`, `PREP_THEME_DEFS`, `PREP_GROUPS`) runs on Scrittura's engine: the `sentences` flag means whole-phrase checking, the comparison and Why; `typeFilter` is Scrittura's own sentence-type filter. Each card has a `rule` (its theme's, or its own as `ownRule`), which Why uses when the preposition is wrong, missing or not needed. Fusion drills (`mech`) are English → Italian like every card (their English is the gloss: *of the book*); `mechPrompt` (*di + il libro*) is shown after answering. Fusion drills are pairs (`PREP_FUSION`: singular, then plural as the item's `pl`), each a short sentence with one fixed verb per preposition — *parlo di*, *vado a* (places), *vengo da* (people and places), *è in* / *sono in* (containers), *è su* / *sono su* (surfaces) — so new nouns must suit their verb; `fused` holds the joined form the tests check, `mechPrompt` the pieces; `cardsForItem` gives the cards that `activeNumbers()` allows (stored with the verb persons under `prepositions`), and `keepPairs` makes `shuffleDeck` / `takeCards` keep a pair together and Ripasso deal both. Every fusion pair must use deck nouns with a natural plural (the suite checks both articles). English prompts must be unique within the section — mark gender with (m.)/(f.) where the English fits both. An apostrophe Italian doesn't have (*del'pane*) is wrong; a missing one is forgiven. The `prepositions` suite checks every drill's article against the deck noun's own article, so new drills must use deck nouns.
- The comparison picks the accepted version with the fewest words swapped, added or dropped (`sentenceCandidates`); a version that only adds an optional word (Io …) must not win.
- Il mazzo salvato (`SAVED_DECK_KEY` = `mazzo-saved-deck-v1`, `deckSnapshot`, `saveDeckNow`, `resumeSavedDeck`, `renderSavedDeck`): the snapshot stores each card once (`cards`, notes stripped — `savedWithNote` re-attaches them from `cardsForItem` on resume) and the pool, focus subset and deck as key lists, plus index (an answered card counts as done; `saveDeckNow(true)` from `render` treats the new card as unanswered), score, streak, missed keys, section or Ripasso labels, direction, `verbMode`, `adjMode`. `savedLive` marks the round as the saved one: `render` and `pagehide`/`visibilitychange` keep the snapshot current; a fresh deck from the setup, `startMixedSession` and `practiseMissed` clear it. `startGame(resume)` takes `{ resumeRound: true, … }` — a click passes its event, so the marker matters — and skips the shuffle. Sync kind `latest` (`syncMergeLatest`: per item, the newer `at` wins). Tests: `tests/saved-deck.test.js`.
- Noun notes: `NOUN_NOTES` (after `NOUN_ITEMS`) holds the notes written in batches, most common first (`NOUN_FREQUENCY_ORDER`); at load each fills `note` on a noun that has none (a noun with its own `note` in `NOUN_ITEMS` keeps it, and the startup check warns on a clash or a key that isn't a noun — keys keep their accents: `città`). Style: one to three sentences; the origin (Latin, Greek, Germanic, Arabic…) only where well established, 'probably' where scholars say so, never folk etymology; then English words that genuinely share it (say so when a look-alike doesn't: *stagione* < *statio*, but 'season' < *satio*); then a tip if useful (false friend, gender, plural, everyday phrase). Italian and Latin in `<em>`, meanings in 'single quotes', no double quotes. `tests/noun-notes.test.js` checks keys, tidiness, length, the English link, and that the commonest nouns are covered first. Progress: 730 of 1061 (400 in `NOUN_NOTES`, in two batches; the 120 nouns of the Nov 2026 topics carry their notes in `NOUN_ITEMS`); 331 still without, the commonest at frequency rank 561. New nouns: add them with their note, slot them into `NOUN_FREQUENCY_ORDER` by the same score (see its comment), and put them in a topic. The nouns page's top is two columns from 900px (`.bench-left`, `.bench-actions`, wrapped only when `cfg.nounMap`; `#game-area` becomes a grid with the map's columns, `.setup-body`/`.setup-main` `display: contents`).
- La mappa (`nounMap: true` on Sostantivi; `nounMapInner`, `mapTopic`, `mapDetailHTML`, `mapWelcomeHTML`, `mapColor`, `wireNounMap`): the nouns page is the map — `container.dataset.map = '1'` widens the page (the rest stays a 660px column), the picks and Start come before it, the theme row is `hidden` (still in the DOM for the shared wiring) and the grid sits in `details.grid-fold`. A line per `NOUN_THEMES` topic, a square per noun from `stats` (the setup's direction), sorted by error rate then tries, untried last, outlined (`.in`) when in the deck. The opened topic (`mapOpen`) is drawn twice — in `#map-panel` beside the map from 900px, and inline under its line below that (CSS shows one). Chips toggle single nouns; *Add all / Take all out / Add the not tried* add to the deck; *Practise just the weakest* replaces it and clicks Start. Every selection change redraws the map on the next frame (`scheduleMapRefresh` from `updateReadout`). It is built from the site's own pieces, so it keeps their look: the theme row's dashed rules and `.theme-eyebrow`, the grid's `.shade-key`, `.person-quick` text links for the sort, the side panels' `.endings` / `.endings-title` / `.en-label` for the panel, *Da ripassare*'s `.weak-row`s for the weakest topics, and the grid's tile styles for the panel's nouns — as `.map-tile` (added to the `.verb-chip` rules), a class of its own so nothing that walks the grid's tiles touches them. The panel's actions are the game's buttons (`submit` to practise the weakest, `submit secondary` to add to the deck). The panel has no scrollbar of its own: it's sticky, and `mapPanelFollow` (on scroll and resize) moves its `top` between 12px and window − panel − 12px via `mapStickTop`, so a tall panel scrolls with the page until its foot shows, holds, and comes back on the way up; opening a topic resets it to its top. Prefs (`hidden`, `sort`) in `mazzo-noun-map-v1`. Tests: `tests/noun-map.test.js`.
- The infinitive first (`wantsInfinitive`, `infinitiveCard`, `infinitiveAnswered`, `currentCard`): before a verb's first form in a conjugation round (EN→IT or Listen, not Ripasso's mixed rounds), `render` shows `verbGate`, the verb's infinitive card, in its place; `handleSubmit` sends it to `infinitiveAnswered`, which records nothing, and *Avanti* or a right retype then shows the same deck card's form (`gatedVerb` pins the infinitive in the meaning line). The setting is `infinitiveFirst` in the verb-persons store; with nothing saved the page default `window.MAZZO_INFINITIVE_FIRST` applies — the test harness sets it false, so suites that drill forms directly don't meet the infinitive card, and `tests/verb-infinitive.test.js` turns it on.
- Conjugations play in order: `shuffleDeck` passes its shuffle through `groupConjugations`, which gathers each verb's person cards (a card with `person`) where the verb first falls, sorted by `personOrder`, leaving other cards in place; with `from`, cards before it (played, on screen) stay put and the verb on screen continues first. The in-round slider adds cards through `verbsFirst` (whole verbs, those in play first) and regroups the unplayed tail; *Focus* uses `shuffleDeck`. `tests/verb-order.test.js` covers it.
- The irregular verbs' forms popout (`conjPattern`, `conjBreaks`, `conjPopHTML`, `wireConjPop`; on for a section with `conjPopout`): a form is highlighted when it differs from the regular pattern of its infinitive (with the *-care/-gare* h, the *-iare* i, and both *-ire* patterns counted as regular); contracted infinitives use the stem their present is built on (`-orre` → `-on`, `-urre` → `-uc`, `CONJ_STEMS` for *dire*, *bere*). It opens after `CONJ_POP.delay` on hover (never while `dragMode` is set), on keyboard focus (not a click's), and on a long press (`CONJ_POP.longPress`), whose release doesn't toggle the tile. `tests/verb-popout.test.js` covers it.
- A spasso (`startPassive`, `passiveStep`, `passiveAdvance`): the round's own cards (`passiveDeck`, as `startGame` deals them) read Italian (`sayText`, `chosenVoice`) then English (`spokenEnglish(card.english)`, `englishVoice`), `passivePrefs.reps` times, then the next card, looping with a reshuffle; records nothing. Each line chains from the last one's end (the first from the tap); a `run` counter discards callbacks from a stopped line; a watchdog carries on after a line that never ends and pauses after one that never starts. It holds a screen Wake Lock (asked again when the page is visible again) and has a hold-to-unlock pocket cover. `tests/passive.test.js` uses a stand-in speech engine and shrinks `PASSIVE_GAPS`.
- The pick grid's shading (`errorShade`, `shadeColor`, `chipShadeAttrs`, `shadeKeyHTML`) reads `stats[key]` for the current direction: the error rate picks the colour (olive → gold → terracotta, saturating at 50% wrong) and the number of tries its strength (faint at one, full from five); untried tiles stay plain. The colour reaches the tile as `--shade` on `.verb-chip.shaded`; `tests/shading.test.js` covers it.
- Parla (`startListening`, `heard`; the microphone sits inside the answer box, `#answer-wrap`; Shift+Enter toggles it) uses the browser's SpeechRecognition (it-IT, up to five guesses): a right guess goes through `handleSubmit` like a typed answer; no right guess marks nothing. Where the browser offers on-device recognition (Chrome's `SpeechRecognition.available`), Parla asks for Italian there (`processLocally`), starts the Italian download if it's offered (listening online meanwhile), and falls back online if refused — left to choose, Chrome can use an English on-device pack. While listening the page's own lang is it-IT too (the fallback for a recogniser that skips its lang); a reply with no Italian word the deck knows and an English tell (`soundsEnglish`) gets a hint on fixing the browser's language. Each recogniser acts only on its own events, a final result ends listening, and listening stops on every new card, the chart and the setup screen. `tests/parla.test.js` drives a stand-in recogniser through the harness's setup hook.
- An empty answer is never checked or counted (`askForAnswer`). Skipping is the *Salta* button (`handleSubmit(true)`; only a strict `true` means skip, since as a click handler `handleSubmit` gets the event): it counts as wrong everywhere, verbs included, then asks for the retype. A test that needs a miss types a wrong answer or presses Salta.
- After a miss, the right answer must be retyped before the next card (`mustRetype`, `retypeCheck`); it uses the same `checkCard` as the answer and records nothing. Tests that simulate a miss must type the right answer before pressing on (`tests/retype.test.js` covers the feature).
- A card with a `person` field is a verb card everywhere (the missed list, the pronoun hint, answer checking). Never put `person` on other cards — a sentence's subject is `sentPerson` (putting `person` on sentence cards once broke the end of every Scrittura round with a miss).
- `sentenceWhy` explains wrong answers from the deck data (adjective forms and slots, verb conjugations, noun gender `g`, articles, joined prepositions). New explanation rules need a case in the `sentences` tests; keep them accurate — a wrong rule is worse than none.

## Story chapters (*La casa di pietra*)

- Present tense only, until the user says they're ready for other tenses. First person: the narrator is the reader. Invented characters only.
- Possessivi (key `possessives`, stores `possessivi-*`): `POSS_DATA` rows are `[theme, person, [it, en, enAlts, literal, itAlts?], plural | null]`, built into phrase items like Preposizioni's pairs (`n.pl`); `possNote` writes the after-answer note (agreement, or why no article, or the join). `POSS_FORM` / `POSS_OWNERS` make possessives a word kind of their own in `sentWordInfo` (`kind: 'poss'`, with owner and slot; *loro* only after an article), which `sentenceWhy` uses everywhere: same owner, wrong form → agreement with the noun; another owner → whose word it is; an extra article before one family member; a missing one before *loro*. Singular/plural is per section now: `numberKey` (`'prepositions'` by default, `'possessivi'` here), with `numberLabel` / `numberNote` for the toggle. The switcher is two rows of six below 1100px.
- Verbi al contrario (`MIPIACE_DATA`): sentence cards like Scrittura's, `type: 'piacere'`, rows `[level, subject, Italian, natural English (the prompt), word for word (the note), alternatives]`; the subject is `'cosa'`/`'cose'` for a thing, else the person who is the subject (for Why and the pronoun-optional answers). The stressed form and the thing-first order are among the alternatives. The validator warns on any unknown word in any accepted answer and on a sentence that's one of Scrittura's. *bastare* and *importare* are `SENT_EXTRA_VERBS`: known to `sentenceSegments` and `sentWordInfo` (so Why explains their agreement) without being cards. The setup shows any section's chart from `SECTION_CHARTS[cfg.panel]`. `tests/mipiace.test.js` covers it.
- Verbi al contrario (key `mipiace`; was *Mi piace* — stores keep their names) is sorted by reading each sentence (`mipiaceTags`): `chi` (the pronoun right before the verb — *gli occhi*, *le scarpe* are articles — or stressed *a me*, or *a* + someone before or straight after the verb; *gli*/*le* split by the English: they/he, formal/she), `cosa` (`una`/`piu` by the verb's form, `fare` with an infinitive, `persona` when the subject is a person), `lemma` (the backwards verb; *fa/fanno male* → *fare male*, *sta/stanno bene* → *stare bene*, a reply with no verb → *piacere*) and `frase`. The setup chooses one way (`facets: true`, `mpFacet`, `mpChooseHTML`, `wireMipiaceFacets`): every tap chooses sentences — OR within a row, AND across rows, nothing tapped = nothing chosen; Select all / Random / Weakest / Clear all reset the taps. `MP_BACKWARDS` (`[verb, means, literally, a deck sentence]`, roughly most common first) is the list on the setup, the table in the in-round chart (left out of the setup's copy: `SECTION_CHARTS.mipiace('setup')`) and each card's note (`mipiaceVerbNote`). `MIPIACE_THEMES` (one per verb) only serve the startup check; `MIPIACE_LEVELS` only order the tiles. New verbs without cards go in `SENT_EXTRA_VERBS` (all six forms — the sentence check reads every person) and `SENT_LIKE` (Why's gloss).
- Dialoghi (`DIALOGUES`): each line is `[speaker, Italian, English word for word, natural English or null]`. The word for word keeps the Italian order and marks "you" where the Italian is formal ("(formal)") or plural ("(you all)"), so English → Italian has one right answer. Every word must be in the deck — `validateSubjects` warns on unknown words, on a line or English prompt used twice, on a line without a speaker, and on a question whose answer or `line` doesn't exist (tests fail on warnings). Each question's `line` is the line that answers it (quoted in the feedback). Keys are `<scene>-<n>`, so reordering a scene's lines moves their history.
- The section is flagged `dialogues` (its home is the scenes, `renderDialogueHome`) and `inOrder` (`shuffleDeck` keeps a scene's lines in order, including *Play all again*). A scene's progress (`mazzo-dialoghi-v1`) has the story's `{ read, quiz }` shape and syncs with `syncMergeStory`. `dialogueVoices` gives the two speakers different voices (different people, not two versions of one voice), or the same voice pitched lower. `tests/dialoghi.test.js` plays scenes through a stand-in speech engine.
- Build each chapter mostly from deck words (check how many resolve to deck cards before adding it); teach the rest through `STORY_WORDS`, each with a meaning, accepted alternatives where useful, and a history note in the usual style.
- Natural, correct Italian matters more than squeezing in vocabulary. Every sentence needs an accurate English translation.
- Every word must resolve: use `senses` for plurals and two-way words (a verb form that is also a noun), `context` when a card's meaning is wider than this use (*paese*: country, here a village). Read through every word's resolution before committing — a tap that teaches the wrong meaning is worse than none.
- Each chapter gets three multiple-choice questions and one *Trova la parola*, a drawing in `STORY_ART` (SVG drawn in code, in the app's palette, gentle animation that `prefers-reduced-motion` turns off) and a pin in `STORY_PINS`.

## Sync

- The app does all merging (`syncMergeAll` and the per-kind rules); the Worker in `worker/` only stores copies and enforces the version check. Keep it that way — the merge rules are tested in jsdom with the rest of the app.
- The Worker's API and `worker/migrations/` change together with `tests/sync-worker.test.js`. Never edit an applied migration; add a new numbered one.
- Deployment is the `deploy-sync` job; it needs the Cloudflare secrets and the `D1_DATABASE_ID` variable and skips quietly without them. The live API is `SYNC_URL` (https://il-mazzo-sync.il-mazzo.workers.dev); its allowed browser origins are in `worker/src/index.js`.
- While the live server predates sign-in (its `/v1/config` is a 404), the app keeps syncing with `SYNC_LEGACY_KEY` (`syncState.legacy`); the new server's 401 for that key ends this and shows the sign-in screen. `tests/fixtures/worker-v1.mjs` is that old server, kept for this test.
- Sign-in is Google only: the app gets an ID token from Google Identity Services and swaps it at `POST /v1/session` for a year-long session; the Worker verifies the RS256 signature against Google's keys, `aud` = `GOOGLE_CLIENT_ID`, issuer, expiry, `email_verified`, and the `ALLOWED_EMAILS` secret (empty = nobody). Never weaken these checks; `sync-worker` tries each way a token can be wrong. `SYNC_LEGACY_KEY` exists only so a first sign-in can move the old built-in key's server copy across (then it's deleted).
- Syncing is invisible by the user's choice: no status line, panel, settings or wording about it in the UI. Keep it that way (the `sync-client` tests check).
- Any new code that saves progress must call `syncTouched()` after writing. Syncing never runs while `container.dataset.view === 'game'`; keep it that way.
- `tests/d1-fixture.js` is the shared D1 stand-in (Node's built-in SQLite with the real migrations).

## Code landmarks (search for these in `index.html`)

- `SUBJECTS` — the five sections (items, themes, frequency order, stats/association keys, panel).
- `cardsForItem`, `render`, `handleSubmit` — card building, display and checking; checkers are `checkAnswer` (nouns), `checkVerbAnswer`, `checkAdjAnswer`, `checkPhraseAnswer`.
- `activePersons(subj)`, `saveVerbPersons` — which persons each verb section drills (`mazzo-verb-persons-v1`, synced); `cardsForItem` builds conjugation cards only for them.
- `refreshDeckSliders`, `handleGameResize` (one slider, id `game-trim-input`), `resizeDeckParts` (two: `game-trim-focus` for the missed/Focus cards, `game-trim-rest`) — the in-round deck size.
- `startGame`, `sessionPool` / `sessionMaxDeck` — sessions; Deck size, Focus and "practise the ones I missed" filter the session pool.
- `srsAnswer`, `dueList`, `startRipasso`, `setCardContext` — spaced repetition and the mixed Ripasso del giorno review. Ripasso covers only `RIPASSO_SECTIONS` (nouns, verbs, irregular, adjectives, story — the words); every other section still schedules its cards (`srsAnswer`) but they don't come up there.
- `speak`, `chosenVoice`, `renderAudioRow` — Italian text-to-speech and Listening mode.
- `STORY_CHAPTERS`, `STORY_WORDS`, `storySegments` / `storyResolveWord` — the story and how each word finds its card; `renderStoryHome`, `renderStoryReader`, `storyShowWord` — the map, the reader and word cards; `STORY_ART`, `storyMapSVG` — the drawings; `startMixedSession` — the mixed round behind both Ripasso and chapter practice.
- `buildBackup`, `restoreFromText`, `storageKeys` — backup and restore.
- `validateSubjects` (runs at start-up) warns in the console about data problems; the tests fail on any such warning.
